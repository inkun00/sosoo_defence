# 전체 기능 검증 · 2026-10-09

## 결과

후속 수정까지 현재 작업공간 전체 자동 테스트 **443개 통과, 실패 0개**. 프런트엔드 TypeScript/Vite 빌드와 Firebase Functions 빌드, 이미지 검사, JavaScript 묶음 검사가 통과했습니다. 아래 최초 검증과 후속 브라우저 검증에서 콘솔 오류는 없었습니다.

실제 두 탭에서 Web Locks를 끈 상태로 각각 5장을 동시에 만들어 **10장 모두 보존**했습니다. 같은 학습지 동시 제출은 한 번만 보상하고, 서로 다른 두 학습지 동시 제출은 서로 다른 영웅 두 명을 보존했습니다. 영웅 선택과 추가 보상도 함께 보존했습니다. 잠금을 가진 탭을 닫으면 대기 중인 다른 탭의 5장 생성이 정상 완료됩니다. 검증 후 원래 저장값을 복원했습니다. 초기의 잠금만 사용하는 구현은 실제 브라우저에서 10장 중 7장만 남아 원본 저장 방식까지 보완했습니다. 이 보장은 학습지·수집 영웅 저장 범위이며 전체 게임 학습 프로필의 탭 간 쓰기를 모두 이전한 것은 아닙니다.

최종 빌드의 Phaser 엔진 **426,502 bytes**, renderer **207,270 bytes**, 발사체 **21,177 bytes**를 합하면 **654,949 bytes**로 기존 대응 묶음 1,117,807 bytes보다 **41.4% 감소**했습니다. 시작 화면의 초기 JS는 **45,149 bytes**, 스토리·PDF는 사용 시점까지 지연됩니다. WebGL/Canvas 모두 실제 이미지 로딩, Sprite 애니메이션, 마스크, 입력, 타이머, Tween, 12종 발사체 명중·효과 정리를 통과했습니다. 개발 서버뿐 아니라 최종 빌드의 모험 화면과 지연 로드된 오프닝도 확인했습니다. [용량 계측](bundle-performance.md)

실제 컴퓨터 대전 화면에서도 로컬 테스트 계정 로그인→상대 선택→60초 준비→`8.8 − 0.1` 정답으로 타워 1개 비축→0코인 전투→비축 타워 무료 설치를 확인했습니다. CPU 타워와 영웅, 몬스터, 체력 게이지, 공격·피격 표시가 표시됐으며 콘솔 오류는 없었습니다.

로컬 Firebase 통합 검사에서 방 입장·예약·권한, 전적 검증·중복 경험치 방지, 회원가입·로그인·비밀번호 재설정·임시 계정 정리 13항목, TURN 발급 제한 13항목을 통과했습니다. TURN 제한은 실제 로컬 Firestore transaction으로 20회 허용·21회 거부·계정별 분리·만료 초기화·클라이언트 읽기/쓰기 차단·만료 정리를 검증했습니다. 임시 계정과 중계 제한 자료는 제거했습니다. 운영 신규 `duelIce`에 대한 비로그인 요청은 HTTP 401로 거부되는 것을 확인했습니다. 외부 자격 서비스의 오류와 4초 지연에서도 실제 WebRTC host↔host UDP 연결, Lv.1/Lv.8 문제판 전달과 60초 전투 전환을 확인했습니다.

## 발견한 문제와 수정

1. **동시 학습지 생성·보상 저장:** 여러 탭의 오래된 localStorage 읽기값 때문에 저장을 덮던 문제. IndexedDB 원본과 transaction으로 생성·암호 제출·영웅 선택을 처리합니다. 기존 학습지와 영웅을 이전하며 페이지 진입 전에 동기 복사본을 갱신합니다. 저장을 사용할 수 없으면 수정 전에 실패 안내를 표시합니다.
2. **P2P 일시 단절 복구:** 기존 데이터 채널이 열린 채로 복구되면 호스트 화면에 끊김 상태가 남던 문제. 유효한 heartbeat/state 수신 시 연결 상태를 복구하고 UI에 알립니다.
3. **두 번째 단절 안내 누락:** 복구 이후의 단절도 다시 안내하도록 알림 상태를 초기화했습니다. 연결이 끊겼을 때 화면의 몬스터 이동 예측도 중단합니다.
4. **오래된 도움말:** 전투 중 설치 문제를 푼다는 설명을 현재의 1분 준비→전투 중 즉시 설치 방식으로 수정했습니다.
5. **자산 검사 기준 누락:** 원래 41개 이미지의 7 MiB 제한에 이후 추가된 15개까지 합산해 실패했습니다. 원래 제한은 유지하고 CPU·영웅 팝업·효과 이미지에는 별도 2 MiB 제한을 적용했습니다.

추가 보완: 페이지 이동 시 소리·Peer·구독을 정리하는 앱이 BFCache로 복원되면 폐기된 런타임을 재사용할 수 있어, 캐시 복원 이벤트에서만 같은 URL을 한 번 새로고침하도록 처리했습니다. 현재 IAB의 실제 뒤로가기는 캐시 없이 다시 로드됐으며, 캐시 복원 분기는 단위 이벤트 3개로 검증했습니다.

## 검증 범위의 한계

- 실제 서로 다른 외부망, 모바일 실기기 GPU/오디오/브라우저 도구 모음 동작은 브라우저 시뮬레이션으로 검증하지 않았습니다. TURN 코드는 배포됐지만 실제 서비스가 미설정이므로 일부 NAT/방화벽에서는 직접 연결이 안 될 수 있습니다. [설정 및 검증 절차](turn-relay-setup.md)
- 일반 사용자 계정 기록을 바꾸거나 메일을 발송하지 않았습니다. 신규 회원가입·비밀번호 재설정·전적 쓰기는 로컬 에뮬레이터로 통합 검증했고 운영 메일 전달과 실제 중계 연결은 별도 검증 대상입니다.
