# 소수의 성

초등학교 4학년 소수의 덧셈과 뺄셈을 배우는 한국어 타워 디펜스입니다. TypeScript·Phaser 3, PC·태블릿 브라우저의 가로 화면을 사용합니다. 전장·상점·구매 계산·성벽 합성·지도·결과 화면을 1280×800 캔버스에 통합하고 기기 크기에 맞춰 축소합니다.

## 실행

Windows에서 `게임실행.cmd`를 열고 `http://localhost:4173`으로 접속합니다. Node.js가 필요하며 실행 창을 열어 두세요. 1인 모험은 인터넷 연결 없이 실행할 수 있습니다. 회원가입·온라인 1:1 대전은 운영 Firebase 연결과 인터넷이 필요합니다. 새 운영 프로젝트 sosoo-defense-20261005를 생성했으며, 계정 설정과 기록 함수 배포를 위한 요금제 연결 승인이 남아 있습니다. 로컬 테스트 절차와 배포 안내는 [FIREBASE.md](FIREBASE.md)를 확인하세요. 태블릿은 같은 네트워크에서 `http://PC의IPv4주소:4173`으로 접속합니다. 방화벽 설정에 따라 접속이 제한될 수 있습니다.

개발용 실행은 `npm install` 후 `npm run dev`, 개발 주소는 `http://localhost:5173`입니다. 원본 코드 ZIP은 `npm run build`로 `dist`를 생성하고 실행합니다. 실행 파일 ZIP에는 `dist`가 포함됩니다.

## 구매하면서 소수 뺄셈 학습

1. 오른쪽 상점에서 타워를 선택하고 길 옆의 빈 칸을 누릅니다. 타워 사이를 가로·세로·대각선 모두 한 칸 이상 비웁니다. 주변의 붉은 표시 칸에는 연속 설치할 수 없습니다. 타워 공격력을 별도로 선택하지 않습니다.
2. 실제 **보유 코인 − 타워 가격 = 남는 코인** 문제가 나옵니다. 계산 중 전투·시간·포탄·몬스터가 멈춥니다.
3. 숫자판 또는 키보드로 답을 입력합니다. 정답이어야 비용을 차감하고 선택한 칸에 설치합니다.
4. 오답은 돈·배치를 유지하고 다시 풀 수 있습니다. 취소·닫기·Esc도 돈을 차감하지 않습니다. 직접 일시정지한 상태는 창을 닫아도 유지됩니다.

기본 등급의 가격은 소수 자리의 받아내림 없이 계산하도록 정합니다. 희귀는 두 자리 소수와 받아내림, 영웅·전설은 4단계부터 세 자리 돈과 연속 받아내림을 우선 제공합니다. 현재 보유금에 맞춰 가격이 바뀌며 상점 카드에서 미리 확인합니다. 보유금의 소수 자리가 모두 9처럼 받아내림을 만들 수 없는 경우에는 해당 금액으로 가능한 뺄셈을 사용합니다. 문제를 열면 가격을 고정하고, 설치 전에 돈·칸·해금·설치 제한을 다시 검증합니다.

모든 학습 식의 피연산자와 정답은 **0 이상 10 미만**입니다. 예: 첫 구매 `8.8 − 0.1 = 8.7`. 기본은 간단한 한 자리 소수, 상위 등급은 소수 자리의 받아내림과 연속 받아내림을 제공합니다. 소수는 정수 천분의 일 단위로 계산하며 답을 반올림하지 않습니다.

| 단계 | 시작 코인 |
|---|---|
| 1 | 8.8 |
| 2 | 8.75 |
| 3 | 8.75 |
| 4 | 8.842 |
| 5 | 8.863 |
| 6 | 8.758 |
| 7 | 8.786 |
| 8 | 8.953 |
| 9 | 8.947 |
| 10 | 9.759 |

타워 가격도 10 미만입니다. 기본은 최대 1, 희귀는 1보다 크고 2 미만, 영웅은 2 이상 3 미만, 전설은 3 이상 4 미만으로 등급 순서를 유지합니다. 단계와 보유금에 따라 소수 부분을 조정합니다. 0.001은 4단계부터 돈에만 사용합니다.

총 보유금의 상한은 없습니다. 보상이 쌓여 10 이상이면 실제 보유금 중 `9 + 현재 소수 부분`만 구매 계산에 사용합니다. 예: 전체 코인이 12.5일 때 계산에 사용할 코인은 9.5입니다. 정답을 맞히면 전체 보유금에서 실제 타워 가격만 차감하고 나머지 코인은 보존합니다. 계산창에 이 관계를 안내합니다. 보상·회수의 덧셈도 결과가 10 미만일 때만 식을 표시하며, 범위를 넘으면 획득 코인만 안내합니다.

후반 보스와 영웅 체력은 최대 9.99로 조정했습니다. 몬스터의 크기·효과·학습 자릿수로 단계 난이도를 구분합니다. 벽돌·대전 블럭의 올바른 덧셈 결과도 10 미만이며, 높은 계정 레벨에서는 `9.00 − 4.78 = 4.22`처럼 소수 부분의 0을 거치는 받아내림을 학습합니다.

## 고유 공격력을 가진 12종 타워

| 타워 | 해금 | 등급 | 한 발 공격력 | 특수효과 |
|---|---|---|---|---|
| 기본 포탑 | 1 | 기본 | 0.1 | 기본 |
| 쌍석포 | 1 | 기본 | 0.2 | 기본 |
| 바늘탑 | 2 | 기본 | 0.01 | 작은 나머지 마무리 |
| 조약돌포 | 2 | 기본 | 0.05 | 기본 |
| 서리탑 | 2 | 희귀 | 0.15 | 3초간 이동 40% 감속 |
| 빙창탑 | 3 | 희귀 | 0.25 | 감속 |
| 투석기 | 3 | 희귀 | 1.2 | 기본 |
| 번개탑 | 4 | 영웅 | 0.35 | 25% 확률로 1.5초 기절 |
| 수정포 | 5 | 영웅 | 0.75 | 기절 |
| 망원포 | 6 | 영웅 | 1.0 | 긴 사거리 |
| 수호 대포 | 6 | 영웅 | 1.5 | 기본 |
| 룬 쇠뇌 | 8 | 전설 | 2.35 | 긴 사거리 |

상점은 6개씩 두 페이지입니다. 공격력은 타입에 고정됩니다. 남은 체력보다 큰 공격은 무효이고 정확히 0일 때만 처치합니다. 예: 체력 1.55에 투석기 1.2를 쏘면 0.35, 번개탑 0.35로 마무리합니다. 같은 상황에도 여러 조합이 가능하므로 보상·별점의 최소 타격은 실제 최적 조합으로 계산합니다.

타워는 자동 공격하며 설치된 타워를 누르면 발사 ON/OFF와 회수를 선택합니다. 회수는 실제 지불한 가격을 반환합니다. 다시 구매할 때도 새 코인 뺄셈을 풀어야 합니다. 특수효과는 추가 피해를 주지 않습니다. 사거리는 일반 174(3칸), 망원 계열 232(4칸) 게임 픽셀로, 한 칸씩 띄운 배치에서도 길을 공격할 수 있게 맞췄습니다. 사거리 안에서 피해를 줄 수 있는 몬스터를 우선하며, 모두 공격력보다 체력이 작으면 기존 초과 공격 규칙을 적용합니다. 타워를 회수하면 주변 설치 제한도 풀립니다. 성벽에는 타워 간격 규칙을 적용하지 않습니다.

## 성벽과 저장

돈 또는 숫자 벽돌을 드롭합니다. 성벽 제작에서 서로 다른 세 벽돌을 `□ + □ = □` 또는 `□ − □ = □` 슬롯에 넣습니다. 값이 맞으면 세 개를 소비해 성벽 하나를 얻습니다. 예: `0.6 + 0.7 = 1.3`, `1.31 − 0.56 = 0.75`. 잘못된 식은 재료를 소비하지 않습니다.

벽돌과 제작한 성벽은 단계 이동·재도전·새로고침에도 같은 브라우저에 보관합니다. 방어 전에 합성·설치하고, 설치한 성벽을 누른 뒤 회수해 다른 칸에 다시 놓을 수 있습니다. 다음 단계에서는 설치했던 성벽이 재고로 돌아옵니다. 성벽은 한 칸이고 파괴되지 않으며 길을 모두 막거나 몬스터를 가둘 수 없습니다. 보유 재고는 제한하지 않고 동시 설치 수만 제한합니다. 벽돌 목록은 6개씩 페이지로 표시합니다.

레벨·해금·별점·음향·난이도도 같은 브라우저에 저장됩니다. 돈과 타워 배치는 단계마다 새로 시작합니다. 이전 저장의 레벨·별점·재고는 유지합니다.

## 난이도와 진행

메뉴 → 난이도 선택에서 연습·표준·도전을 고릅니다. 기본은 표준입니다. 방어 시작 전에 타워·성벽을 모두 회수한 상태에서 변경합니다.

| 난이도 | 1단계 타워 | 2단계 | 3~5단계 | 6~10단계 | 바늘탑 | 설치 성벽 |
|---|---|---|---|---|---|---|
| 연습 | 4 | 8 | 12 | 17 | 최대 4 | 최대 6 |
| 표준 | 3 | 6 | 10 | 14 | 최대 3 | 최대 4 |
| 도전 | 2 | 5 | 9 | 13 | 최대 2 | 최대 3 |

바늘탑은 전체 타워 수에 포함합니다. 표준 기본 이동 속도는 1단계 27 → 10단계 34.2px/s, 도전은 표준보다 12% 빠릅니다. 연습은 초반 27·후반 24px/s입니다. 몬스터 종류별 속도와 감속·기절을 추가 적용합니다.

단계당 2분, 한 웨이브, 12마리입니다. 첫 등장 8초, 이후 8.4초 간격입니다. 방어와 학습 목표를 모두 달성해야 진급합니다. 발사 ON/OFF 사용 횟수 목표는 없습니다. 일시정지와 선택적인 2배속, 계산 도움말, 효과음·배경음 설정을 제공합니다.

## 학습 순서와 몬스터

지도서 한대희(4-2) 3단원의 소수 자릿값·크기 비교·덧셈·뺄셈 순서를 10단계로 연결했습니다. 구매 뺄셈은 실제 돈과 설치 행동, 전투 뺄셈은 실제 체력 변화, 성벽 덧셈·뺄셈은 실제 벽돌 소비에 연결합니다.

| 단계 | 주요 학습 |
|---|---|
| 1 | 0.1·0.2와 한 자리 소수, 간단한 코인 뺄셈 |
| 2 | 0.01·두 자리 소수, 서로 다른 공격력 |
| 3 | 자릿값과 크기 비교, 1.2·0.25 등의 조합 |
| 4 | 돈의 0.001, 구매 뺄셈 정답 2회 |
| 5 | 단위 관계와 다양한 소수 크기 |
| 6 | 한 자리 덧셈과 받아올림, 성벽 준비 |
| 7 | 두 자리 덧셈과 받아올림, 성벽 2개 준비 |
| 8 | 1을 0.1 열 개로 바꾸어 빼기 |
| 9 | 0.1을 0.01 열 개로 바꾸어 빼기 |
| 10 | 구매·전투·성벽 소수 계산의 종합 적용 |

돌 슬라임 → 바위 갑충 → 철갑 골렘 → 수정 거인 → 고대 돌왕으로 확대됩니다. 최대 체력은 단계별 0.6 / 0.95 / 3.75 / 5.68 / 8.95 / 9.68 / 9.75 / 9.87 / 9.89 / 9.99입니다. 보스도 표시 체력을 정확히 0으로 만들어야 합니다.

## 그래픽과 조작

내장 imagegen으로 생성한 원본 PNG를 보존합니다. 새 `tower-heads-a-v1.png`·`tower-heads-b-v1.png`는 각각 3×2칸으로 총 12종 회전 포신입니다. 고정 받침대 위에서 몬스터를 조준하고 발사 반동을 표시합니다. 발사 섬광·궤적·기본/서리/번개/장거리 명중·돌 파편·충격파는 기존 효과 시트를 함께 사용합니다. 큰 공격은 전장만 짧게 흔듭니다. 5종 몬스터는 각각 걷기·피격·감속·퇴장 16프레임입니다.

1인 모험은 14개, 1:1 대전은 영웅·돌 알을 포함해 25개 이미지 파일을 로드합니다. 초기 4종 단독 타워 원본도 프로젝트에 보존하므로 `public/assets/dungeon`에는 총 29개 원본 PNG가 있습니다. 모든 생성 프롬프트는 `prompts.json`, 새 타워 프롬프트·원본 저장 경로는 `tower-catalog-prompts.json`, 영웅 30종·걷기 120프레임은 `hero-prompts-v1.json`, 돌 알 10단계는 `egg-prompts-v1.json`, 출처는 `public/CREDITS.txt`에 있습니다. 사용자 제공 언더다크 디펜스 영상은 분위기 참고이며 해당 게임 그림을 복사하지 않았습니다.

모션 감소 설정은 화면 흔들림·반동·강한 효과를 생략하며 필수 구매 문제는 유지합니다. 키보드: 방향키·Enter로 칸 선택, 숫자·소수점·Backspace·Enter로 구매 문제 입력, Space 일시정지, F 성벽 제작, Esc 닫기. Tab과 Enter로 조작 버튼도 사용할 수 있습니다. 캔버스 UI와 별도로 화면 읽기 조작 버튼·문제 안내·게임 상태를 제공합니다.

## 검증과 배포

`npm test`: 98개 규칙·구매·저장·난이도·한 자리 자연수 범위 테스트. 세 난이도 × 10단계의 실제 코인 뺄셈 정답·구매·발사 조절·합성·재배치 공략을 포함합니다. 공략은 예산·설치 제한을 지키고 재배치에도 기존 쿨다운을 이어갑니다. 학생 대상 난이도 평가는 별도로 필요합니다.

`npm run build`: TypeScript 검사와 배포용 Vite 빌드.

개발 서버를 실행한 뒤 `node tools/browser-check.cjs`로 구매 문제·오답·취소·정답 설치·전투 정지·재개·성벽·지도·저장·PC·태블릿을 확인합니다. `turret-check.cjs`, `combat-fx-check.cjs`, `difficulty-check.cjs`, `inventory-check.cjs`는 세부 검증입니다. `production-check.cjs`는 완성본의 실제 구매·전투 흐름을 확인합니다. Chromium이 없다면 `npx playwright install chromium`, 다른 실행 경로는 `PLAYWRIGHT_CHROMIUM_EXECUTABLE`로 지정합니다.

`python tools/package-release.py`는 실행 파일 ZIP과 원본 코드 ZIP을 갱신하고 압축 무결성을 검사합니다. 원본은 `src`, 완성본은 `dist`, 화면 확인 자료는 `test-results`, 배포 파일은 상위 `output/decimal-defense`에 있습니다.

## 회원가입과 1:1 대전

메뉴의 **회원가입 · 1:1 대전**으로 이동합니다. 가입·로그인 후 중앙 방 목록에서 공개방 또는 비밀번호 방으로 참가하고 함께 준비 완료를 누릅니다. 방은 게임 시작 또는 생성 후 5분이 지나면 목록에서 사라집니다. 접속 정보는 자동 교환합니다. WebRTC로 호스트 컴퓨터에 연결하며 전투는 호스트 브라우저가 진행합니다. Firebase는 대기 방 목록과 접속 정보를 관리하고, 경기 종료 후 승·패·경험치·계정 레벨·오답 문항을 저장합니다. 대기실의 전적 · 오답 복습에서 확인할 수 있습니다. 직선 길의 양쪽 불꽃을 타워로 방어하면서, 동일한 소수 블럭 16개로 덧셈·뺄셈을 맞혀 돌 알을 성장시킵니다. 현재 알 레벨의 영웅 3종 중 하나를 골라 부화시켜 상대 불꽃을 공격합니다. 영웅은 레벨 1~10, 각 3종씩 총 30종으로 별도 생성했습니다. 기본 웨이브와 영웅이 함께 진행합니다.

Firebase를 차단한 상태의 두 브라우저 직접 대전과 종료 후 에뮬레이터 기록 저장을 확인했습니다. 기본은 같은 Wi-Fi/LAN이며 서로 다른 인터넷에는 선택 가능한 STUN 주소 보조가 있습니다. 게임 중계 서버는 구성하지 않아 네트워크에 따라 직접 연결이 제한됩니다. 호스트 창을 열어 두고 새로고침하지 마세요. 새 Firebase 프로젝트와 웹 앱·기본 Firestore는 생성했으며, 기록·방 목록·만료 정리 함수의 운영 배포는 Blaze 요금제 승인을 기다립니다. 자세한 게임 규칙, 계정 연결과 배포 절차는 [FIREBASE.md](FIREBASE.md)에 있습니다.

## 몬스터 피격 뺄셈식

몬스터가 포탄에 맞으면 머리 위에 `기존 체력 − 공격력 = 남은 체력`이 뜹니다. 처치 타격도 `0.1 − 0.1 = 0.0`처럼 0까지 표시합니다. 수식은 몬스터를 따라가며 약 2.2초 동안 표시되고, 같은 몬스터가 다시 맞으면 최신 계산으로 바뀝니다. 소수 자릿수를 맞추고, 화면 가장자리에서 잘리지 않게 배치합니다. 피해가 무효인 공격은 성공한 뺄셈식으로 표시하지 않습니다.

기본값은 ON입니다. **메뉴 → 화면 · 효과음 · 배경음 → 몬스터 피격 뺄셈식**에서 ON/OFF를 바꿉니다. OFF는 떠 있던 식도 즉시 지웁니다. 설정은 같은 브라우저에 저장되며 1인 모험과 1:1 대전이 공유합니다. 대전은 상단 **설정** 또는 대기실의 **게임 설정**에서 변경할 수 있습니다. 모션 감소 설정에서도 수식은 표시합니다.

`node tools/hit-equations-check.cjs`는 실제 피격 계산, 위치·이동·가장자리, 처치, 여러 포탄의 순서, ON/OFF 즉시 반영·재접속 저장·모드 공유, PC·태블릿·모션 감소를 검증합니다.


1:1 블럭은 정답을 보장하는 `a + b = c` 세트 5개와 같은 세트에 참여하는 추가 블럭 1개로 16칸을 채워 섞습니다. 모든 블럭이 덧셈·뺄셈 조합에 참여합니다. 승리 경험치로 올라간 계정 레벨을 기준으로 계산 난이도를 정하며, 서로 다른 레벨은 낮은 쪽에 맞춥니다. 한 자리 소수 → 두 자리 소수 → 받아올림·연속 받아내림 → 0을 거치는 받아내림 순으로 확장됩니다. 학습 난이도는 경기 중 고정되고, 풀이 속도가 달라도 같은 순서의 문제판을 받습니다.


## GitHub와 Vercel

원본 저장소: [inkun00/sosoo_defence](https://github.com/inkun00/sosoo_defence). 저장소 루트가 게임 프로젝트이며 Node.js 22, `npm ci`, `npm run build`, 출력 디렉터리 `dist`를 사용합니다. `vercel.json`에 Vite 배포 설정이 있습니다. GitHub의 `main`을 Vercel에 연결하면 이후 push도 자동 배포됩니다.

Vercel은 게임 웹 화면을 호스팅합니다. 회원가입·중앙 방 목록·경기 기록은 Firebase 운영 설정과 함수 배포가 완료되어야 사용 가능합니다. 준비 전에는 `VITE_FIREBASE_AUTH_READY=false`, `VITE_FIREBASE_RECORDS_READY=false`, `VITE_FIREBASE_LOBBY_READY=false`를 유지합니다. 공개 Firebase 웹 설정 네 항목은 Vercel 환경 변수에 입력하며, 서버 자격 증명과 로컬 `.env.local`은 Git에 올리지 않습니다. 로컬 에뮬레이터 연결은 localhost에서만 허용합니다.

공식 배포 안내: [Vite on Vercel](https://vercel.com/docs/frameworks/frontend/vite), [GitHub 자동 배포](https://vercel.com/docs/git/vercel-for-github).
